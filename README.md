# Zapas — прогноз запасов для общепита

Система снимает с владельца кофейни или кафе вопрос «всё ли у нас есть».
Она ведёт склад, прогнозирует спрос на 14 дней вперёд и заранее напоминает,
что и когда заказать.

> Учебный проект уровня Junior Full Stack, не коммерческий продукт.
> Полное ТЗ — [docs/spec.md](docs/spec.md).

**Работает здесь:** https://vitalness.ru/zapas/

Кнопка «Открыть демо» заводит отдельную организацию с полугодом истории
и пускает в неё без регистрации. Кнопки «+1 день» и «+7 дней» проматывают
виртуальное время — прогноз видно в работе, не дожидаясь недели.

## Что делает

| Блок | Вопрос владельца | Ответ системы |
|---|---|---|
| Склад | Что есть прямо сейчас? | Приход, расход, списания, инвентаризация, остаток и «в пути» |
| Прогноз | Сколько понадобится? | Расход на 14 дней по истории с учётом дня недели, с показанной точностью |
| Напоминание | Когда и сколько заказать? | Точка заказа с учётом срока и дней поставки, сводка и срочные алерты |

## Стек

Go 1.26 · chi · pgx + sqlc · PostgreSQL 16 с RLS · Redis + asynq ·
React 19 + TypeScript + Vite · Tailwind · nginx · systemd

Без ORM, без `time.Now()` в бизнес-логике, без float для количеств —
причины в [CONVENTIONS.md](CONVENTIONS.md) и [docs/adr/](docs/adr/).

## Запуск

Нужен только Docker: локальный Go-тулчейн не требуется, всё собирается
и тестируется в контейнере.

```bash
cp .env.example .env
make dev          # postgres, redis, mailpit + миграции
make test         # тесты с детектором гонок
```

Полезное:

```bash
make help            # список целей
make migrate-status  # состояние миграций
make cover           # покрытие пакетов ядра
make reset-db        # снести том БД и накатить схему заново
```

Под Windows Go-команды удобно гонять напрямую:

```powershell
.\scripts\go.ps1 test ./... -race
.\scripts\app.ps1 migrate up
```

## Устройство

```
cmd/app/            точка входа: api | worker | migrate | seed
internal/
  platform/         конфиг, БД, HTTP, логи, метрики, тип количества
  clock/            интерфейс Clock и календарный день
  auth/ tenant/     сессии, роли, изоляция тенантов
  catalog/ stock/   номенклатура, движения, остатки, инвентаризация
  forecast/         модели M1 и M2, бэктест — чистые функции
  replenishment/    окна поставки, точка заказа, статусы — чистые функции
  orders/ notify/   заказы поставщику, outbox, Telegram, email
  sandbox/          генератор данных, симулятор времени, очистка
queries/            SQL для sqlc
migrations/         SQL-миграции goose
web/ landing/       SPA кабинета и лендинг
deploy/ docs/
```

Подробнее — [docs/architecture.md](docs/architecture.md) и семь решений
в [docs/adr/](docs/adr/).

Три вещи, вокруг которых собрано остальное:

- **Остаток никогда не редактируется напрямую.** Он равен сумме неизменяемых
  движений, и любую цифру можно объяснить по журналу ([ADR-002](docs/adr/0002-movement-journal.md)).
- **Данные тенантов не смешиваются.** Четыре уровня защиты, включая RLS в базе
  ([ADR-005](docs/adr/0005-tenant-isolation.md)).
- **Время берётся через `Clock`, а не через `time.Now()`.** На этом держится
  «промотка времени» в демо ([ADR-006](docs/adr/0006-clock.md)).

## Состояние

| Неделя | Результат | Статус |
|---|---|---|
| 0 | Репозиторий, compose, каркас, схема БД с RLS, CI, docs и ADR | готово |
| 1 | Вход, тенанты, каталог, движения, остатки, инвентаризация, импорт CSV | готово |
| 2 | Генератор данных, дневной расход, модели M1 и M2, бэктест | готово |
| 3 | Окна поставки, точка заказа, статусы, заказы, outbox, Telegram, воркер | готово |
| 4 | Дашборд, карточка позиции, песочница, симулятор, автопилот | готово |
| 5 | Лендинг, деплой, бэкапы, сторож, k6, OpenAPI, раннбуки | готово |

Пакеты `forecast` и `replenishment` закрыты табличными тестами: пример расчёта
окон поставки из §5.1 и блок «почему такой статус» из §6.2 проверяются дословно,
цель по точности прогноза (WAPE ≤ 20%) — автотестом с фиксированным seed.

Склад и API проверяются на настоящем PostgreSQL: обязательные тесты §14.1
(конкурентность, идемпотентность, изоляция) зелёные, включая 50 горутин,
одновременно списывающих одну позицию.

Локальный тенант для разработки создаётся командой `make seed`:
вход `owner@zapas.local` / `локальный-пароль-42`.

Демо-тенант с полугодом истории поднимается на проде за 1,5 с при
бюджете 3 с и живёт 24 часа; автопилот показывает разницу «с системой
и без».

## Прод

Система работает на общем сервере, где кроме неё живут ещё пять
проектов, — 1 vCPU и 961 МБ ОЗУ на всех. Это определило почти все
решения по размещению:

| | |
|---|---|
| Размещение | systemd, не Docker: под контейнеры на этой машине нет памяти |
| База | существующий кластер PostgreSQL 16, отдельная база и три роли |
| Адрес | `vitalness.ru/zapas/` — путь на домене портфолио; префикс срезает nginx, приложение о нём знает только из `APP_BASE_URL` |
| HTTPS | Let's Encrypt на vitalness.ru |
| Бэкапы | ежедневно в 04:00, 7 дневных и 4 недельных копии |
| Наблюдение | `/metrics` в формате Prometheus плюс сторож, пишущий в Telegram |

Нагрузочный прогон делается на локальной машине, а не на этом сервере:
гонять k6 по общему хосту, где у соседнего проекта настоящие
посетители, нельзя. На базе с миллионом движений дашборд отвечает за
22,7 мс при бюджете 300 мс, запись движения — за 34,2 мс при бюджете
150 мс. На самом сервере при живых данных дашборд собирается за 5–8 мс,
а демо создаётся за 1,5 с при бюджете 3 с. Подробности и планы
запросов — в [docs/performance/](docs/performance/README.md).

На чём споткнулся по дороге и что из этого вынес — в
[docs/journal.md](docs/journal.md).

Как это поддерживать — в [docs/maintenance.md](docs/maintenance.md):
от первого коммита и настройки CI до регулярных проверок и пределов
текущего размещения. Что делать, когда сломалось, — в
[docs/runbooks/](docs/runbooks/README.md): выкат, откат, восстановление
из бэкапа и злоупотребление демо.

Контракт API — [docs/api/openapi.yaml](docs/api/openapi.yaml),
42 операции, проходит `redocly lint`.
