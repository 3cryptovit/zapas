# Правила проекта

Проект: **Zapas** — система прогноза запасов для общепита. Полное ТЗ: `docs/spec.md`.
Рабочее имя `zapas` — открытый вопрос ТЗ (15.3), меняется одним `go mod edit` + заменой импортов.

## Стек

| Слой | Выбор |
|---|---|
| Backend | Go 1.26, роутер `chi` |
| БД | PostgreSQL 16, `pgx/v5` + `sqlc` (без ORM) |
| Миграции | `goose`, SQL-файлы в `migrations/` |
| Очереди | Redis + `asynq` |
| Логи | `log/slog`, JSON |
| Frontend | React + TypeScript + Vite, TanStack Query, Recharts, Tailwind |
| Тесты | `go test`, `testcontainers-go`, Vitest, Playwright, k6 |

## Структура

```

internal/

  auth/             сессии, пароли, роли, CSRF
  tenant/           тенанты, контекст тенанта, RLS
  catalog/          позиции, категории, поставщики, импорт CSV

  forecast/         ряды, модели, бэктест (чистые функции)
  forecast/pipeline ночной пересчёт: сборка ряда, запись прогноза
  replenishment/    окна поставки, точка заказа, статусы
  orders/           заказы поставщику, приёмка
  dashboard/        read-модель главного экрана и карточки позиции
  notify/           outbox, сводки, Telegram, email
  sandbox/          генератор данных, симулятор времени, очистка

web/ landing/       SPA кабинета и лендинг

```

## Запреты

1. **Без ORM.** Только `sqlc` + параметризованные запросы. Ручной `fmt.Sprintf` в SQL — нет.
2. **Без `time.Now()`** нигде, кроме `internal/clock` и `main`. Время берётся из `clock.Clock` (ADR-006).
   Это касается и тестов: часы там заморожены, и «час назад» по системным часам
   может оказаться будущим по замороженным. Дважды ловило — в приёмке заказа
   и в тесте очистки песочницы.
3. **Без `float64` для количеств и денег.** Только `decimal.Decimal` / `numeric(14,3)`.
4. **Без правки применённых миграций.** Ошибку исправляет новая миграция.
5. **Без `tenant_id` из тела запроса или URL.** Только из сессии (§12.1).
6. **Без изменения `stock_movements`.** Таблица append-only; исправление — `reversal`.
7. **Без бизнес-логики в HTTP-хендлерах.** Слои: handler → service → repository.
8. **Без прямых запросов в таблицы чужого модуля.** Только через интерфейс модуля.
   Исключение — read-модель дашборда (`item_status`).
9. **Без `COPY FROM`.** PostgreSQL не поддерживает его для таблиц с RLS.
   Пакетная запись — через разворот массивов `unnest` (ADR-005).

## Команды

Интеграционные тесты идут на настоящем PostgreSQL. Адрес кластера —
в `TEST_DATABASE_ADMIN_URL`; без него они пропускаются, а не падают.

```
make dev            поднять локальное окружение (postgres, redis, mailpit, api, worker, vite)
make seed           создать локального тенанта для разработки
make migrate        goose up
make sqlc           sqlc generate (CI проверяет, что дифф пустой)
make test           go test ./... -race
make test-int       интеграционные тесты (testcontainers, нужен Docker)
make lint           golangci-lint + eslint + tsc --noEmit + gitleaks
make e2e            Playwright по сценарию песочницы
```

Go-тулчейн локально может отсутствовать — всё то же самое работает через
`make docker-test` (контейнер `golang:1.26`).

## Контракты между модулями

Стоили дороже всего, поэтому записаны явно:

- **«Сейчас» для события бизнеса — всегда время тенанта** (`t.Now(clock)`),
  системные часы только для технических отметок вроде `updated_at`.
  В песочнице часы сдвинуты, и системное время делает приход «прошлым».
- **Статус заказа меняется до создания движений**, а не после: иначе
  пересчёт видит заказ ещё отправленным и считает его количество в пути.
- **Пересчёт статуса позиции — в той же транзакции, что и движение.**
- **Чужой ресурс — 404, а не 403**: по 403 видно, что объект существует.
- **Новая таблица с данными организации обязана получить политику RLS.**

## Порядок работы

1. Фича начинается с `docs/features/<name>.md` по шаблону: контекст → требования
   и крайние случаи → изменения API и схемы → план тестов → оценка в часах → факт.
2. Небольшие шаги, после каждого `make test` зелёный.
3. Каждое требование FR-1…FR-21 закрыто тестом; номер FR указывается в имени теста.
4. Заметный случай — запись в `docs/journal.md`: что сломалось и почему.

Подробнее — [docs/process.md](docs/process.md): классификация ошибок и
порядок сессии.

## Готово значит

- [ ] `make test` зелёный
- [ ] `make api-lint` зелёный, если API менялся
- [ ] Наблюдаемый результат проверен глазами, а не по коду ответа
- [ ] Крайние случаи из файла задачи закрыты тестами
- [ ] Предпосылки о среде подтверждены выводом команд
- [ ] Файл задачи дописан: решения, статус, факт
- [ ] Документация изменена тем же коммитом, что и код

## Договорённости по коду

- Ошибки: `fmt.Errorf("...: %w", err)`, доменные — типизированные (`stock.ErrInsufficientStock`).
- HTTP-ошибки: RFC 9457 (`application/problem+json`), рендер один — `platform/httpx`.
- Репозиторий принимает `tenantID` явным первым аргументом после `ctx`.
- Каждая транзакция начинается с `SET LOCAL app.tenant_id` (`tenant.WithTx`).
- Чужой ресурс — `404`, не `403`.
- Количества в JSON — строки: `"12.500"`.
- Логи без паролей, токенов и тел запросов.
