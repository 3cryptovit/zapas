# Фича: GitHub и CI/CD

Разовая настройка репозитория и пайплайна плюс приведение проверок
в состояние, при котором первый push не краснеет.

> Статус: готово
> Оценка: 3 ч · Факт: 3 ч

## Контекст и цель

Workflow-файлы в проекте лежали, но ни разу не запускались: коммитов
не было. Задача — убедиться, что они запустятся и пройдут, и написать
владельцу порядок действий.

## Предпосылки

| Утверждение | Чем проверено | Вывод |
|---|---|---|
| Коммитов и remote нет | `git log`, `git remote -v` | Пусто — настройка с нуля |
| `npm ci` найдёт lock-файлы | `ls web/package-lock.json landing/package-lock.json` | Оба на месте |
| Сгенерированный код не отстал | `sqlc diff` в контейнере | Совпадает |
| Секретов в дереве нет | `gitleaks detect --no-git` | Находок ноль |
| Линтер проходит | `golangci-lint run` | **41 замечание** — CI упал бы |
| Версия линтера в CI читает наш конфиг | `golangci-lint --version` против `version: "2"` в `.golangci.yml` | **Нет:** action v6 ставит линтер v1 |

Две последние строки и есть содержание задачи.

## Что сделано

### Настоящие дефекты

**Подделка адреса клиента.** `middleware.RealIP` из chi переписывает
`RemoteAddr` из заголовка, который присылает сам клиент. От
`RemoteAddr` зависят оба ограничителя — пять демо в час (§7.5) и защита
от перебора пароля (§12.2), — то есть любой мог снять их, добавив
`X-Forwarded-For`. На публичном адресе это открытая дверь к
неограниченному созданию демо на машине с 961 МБ ОЗУ.

Заменено на `httpx.RealIP`: заголовку верим только от прокси на петле,
снаружи он игнорируется целиком. Приложение слушает `127.0.0.1`,
снаружи к нему можно попасть лишь через nginx, а тот заполняет
`X-Real-IP` настоящим адресом соединения. Закрыто таблицей тестов на
четыре случая.

**Необработанные ошибки закрытия** (10 мест), сравнение ошибки через
`==` вместо `errors.Is`, шесть упрощений из staticcheck.

### Ложные срабатывания

Закрыты в `.golangci.yml` по одному, каждое с причиной: пароли
локальных фикстур, CSRF-cookie без `HttpOnly` (так работает двойная
отправка, ADR-007), `math/rand` в генераторе демо (воспроизводимость —
требование §7.2), ограниченный дважды разбор формы, преобразования
`int` в короткие типы от уже проверенных величин.

### Пайплайн

| Правка | Причина |
|---|---|
| `golangci-lint-action` v6 → v7, версия прибита | v6 ставит линтер первой версии, наш конфиг формата 2 |
| Та же версия прибита в `Makefile` | Локально и в CI должен работать один инструмент |
| В работу «Фронтенд» добавлена сборка лендинга | Ломалась бы впервые при выкате |

## Крайние случаи

- Первый push в пустой репозиторий — не должно быть конфликта с
  автосозданными README и лицензией: в гайде сказано их не добавлять.
- Windows и переводы строк — закрыто `.gitattributes`.
- Защита ветки ломает прямой push — в гайде показан обход через PR.
- Секрет нельзя прочитать обратно — сказано в гайде.

## Как проверю

Все восемь проверок CI прогнаны локально теми же командами, что стоят
в пайплайне.

| Проверка | Результат |
|---|---|
| `gofmt` | чисто |
| `go vet` | чисто |
| `golangci-lint run` | **0 issues** (было 41) |
| `go test -race` | 14 пакетов, провалов нет |
| `sqlc diff` | совпадает |
| `gitleaks` | находок нет |
| eslint, tsc, vitest, сборка | 26 тестов, чисто |
| `redocly lint` | валиден, 1 предупреждение (лицензия) |

## Чего не проверено

Запуск в самом GitHub. Локально воспроизведены команды, но не
окружение: доступность Go 1.26 в `setup-go`, работа
`gitleaks-action` на личном аккаунте, сервисные контейнеры. Это
выяснится на первом push — в гайде есть таблица разбора красной сборки.
