> Статус: черновик
> Оценка: 4 ч (каркас и смоук) + 8 ч (полный сценарий) · Факт: —

## Контекст и цель

Два самых дорогих дефекта проекта не видел ни один серверный тест:

- кабинет отдавал `200` на страницу и `403` на все её скрипты — белый
  экран при идеальных логах, жил с первого дня выката;
- кнопка «Открыть демо» вела на адрес без слеша, браузер переходил и
  показывал лендинг вместо кабинета.

Оба нашлись только тогда, когда человек открыл страницу глазами. Нужен
тест, который делает это сам: грузит страницу в настоящем браузере,
выполняет скрипты и смотрит на результат.

## Предпосылки

| Утверждение | Чем проверено | Вывод |
|---|---|---|
| Node подходящей версии есть | `node -v` | `v24.11.0` — подходит |
| Playwright ещё не установлен | `package.json` | `не установлен` — ставить с нуля |
| Места под браузеры хватит (нужно ~500 МБ) | `df -h /c` | `8.1G` свободно — хватит |
| Прод отвечает и годится как цель | `curl /app/` | `200` |
| Тестовый раннер уже есть и его не ломать | `package.json` | `vitest ^2.1.0` — Playwright ставится рядом, отдельной командой |

Отдельно проверить перед началом: **создание демо ограничено пятью в
час с одного адреса.** Тест, создающий демо на каждый прогон, упрётся в
лимит. Решение выбрать в ходе работы: либо один прогон на сессию, либо
вход под заранее заведённой учёткой.

## Требования и крайние случаи

| # | Требование | Крайний случай |
|---|---|---|
| 1 | Лендинг открывается, кнопка демо работает | Демо уже открыто — повторный клик возвращает в него же, а не создаёт второе |
| 2 | Кабинет загружается целиком | **Ни одного запроса с 4xx или 5xx**, включая скрипты и стили |
| 3 | В консоли браузера нет ошибок | Предупреждения допустимы, ошибки — нет |
| 4 | Дашборд показывает позиции | Пустая организация: показывает приглашение завести позиции, а не пустоту |
| 5 | Прямой заход на внутренний адрес | `/app/orders` в адресной строке открывает заказы, а не редирект на вход |
| 6 | Адрес без слеша | `/app` приводит в кабинет |

Крайние случаи по обязательному списку:

- пусто — организация без позиций;
- предел — дашборд на 300 позициях не должен подвешивать страницу;
- повтор — второе нажатие кнопки демо;
- чужой ресурс — `/app/items/<id из другого демо>` показывает «не
  найдено», а не чужие данные.

## Изменения API и схемы

Нет. Тест только читает.

## Как проверю

| Что | Как выглядит успех |
|---|---|
| Автоматически | Прогон падает, если в консоли есть ошибка или хоть один запрос вернул не 2xx/3xx |
| Проверка самого теста | Временно вернуть `alias` в regex-локацию nginx локально — тест обязан упасть |

Второе важнее первого. Тест, который никогда не падал, ничего не
доказывает: ровно так зелёный прогон k6 измерял скорость ответа `401`.

## План

1. Поставить Playwright в `web/`, один браузер (chromium).
2. Смоук: лендинг → демо → дашборд, сборщики ошибок консоли и неудачных
   запросов.
3. Убедиться, что тест падает на воспроизведённом дефекте.
4. Полный сценарий из ТЗ: демо → +7 дней → напоминание → заказ →
   приёмка → позиция зелёная.
5. Подключить к CI против локально поднятого окружения.
6. Добавить прогон смоука в `scripts/deploy.sh` после выката.
