# Фича: пошаговое демо

Четвёртая из четырёх задач «личный сайт + Zapas на своём домене».
Расширяет §7 (песочница).

> Статус: готово, на проде с 2026-09-26 14:47 UTC
> Оценка: 10 ч · Факт: 6 ч

## Контекст и цель

Готовое демо показывает результат: 90 дней работы кофейни уже случились,
дашборд красный, прогноз посчитан. Но не видно, **как** к этому прийти:
что система спрашивает у владельца и в каком порядке.

Пошаговое демо начинается с пустой организации. Слева направо — шаги
настоящего внедрения. Каждый шаг можно сделать руками в обычном
интерфейсе или нажать «заполнить тестовыми данными»: посетитель видит
алгоритм, а рутину закрывают шаблоны. Вход — по сгенерированному логину
и паролю, которые показываются посетителю: так видно и вход, и то, что
демо у каждого своё.

Готовое демо остаётся второй кнопкой: у рекрутера может быть две минуты.

## Требования и крайние случаи

| # | Случай | Ответ |
|---|---|---|
| 1 | Пусто: только что созданное пошаговое демо | Текущий шаг — «Поставщики»; у остальных шагов нет кнопок, действовать можно только в текущем |
| 2 | Шаг не по порядку: «заполнить позиции» без поставщиков | API: 409 и текст «сначала — шаг „Поставщики“». В интерфейсе до этого не дойти: кнопка есть только у текущего шага |
| 3 | Повтор: «заполнить» дважды | Ничего не дублируется: поставщики и позиции — по имени, история — по наличию, пересчёт, заказ и приёмка — по статусу. Ответ 200 с тем же состоянием |
| 4 | Одновременность: два «заполнить» из двух вкладок | Сессионная advisory-блокировка на тенанта; второй получает 409 «уже заполняется» |
| 5 | Смесь: посетитель завёл поставщика «Молочная ферма» руками | Шаблон его не дублирует, позиции цепляются к нему |
| 6 | Позиции посетителя без шаблона | Истории и расхода при промотке у них нет — «нет прогноза», честно. Шаг 3 без шаблонных позиций — 409 с подсказкой |
| 7 | Ноль: заказывать нечего | Шаг 6 отвечает 409 «сейчас заказывать нечего», а не создаёт пустой заказ |
| 8 | Ручное движение до наполнения историей | Остаток = сумма журнала (история дописывает дельту). Проверяется тестом |
| 9 | Готовое демо | Справочники, история и прогноз отмечены; пересчёта генератор не делает, поэтому текущий шаг — «Пересчёт». Панель свёрнута |
| 10 | Пароль | Показывается один раз в ответе на создание; фронтенд держит его в localStorage для этого `tenant_id`. Сервер хранит только хеш |
| 11 | Повторный клик по кнопке демо | Как раньше: живое демо возвращается, лимит не тратится; логина в ответе нет — он уже у посетителя |
| 12 | «Сбросить демо» в пошаговом | Новое пошаговое с новым логином |
| 13 | Предел: 5 демо в час с адреса, 60 живых | Пошаговое считается наравне с готовым |
| 14 | Аварийное выключение | `SANDBOX_DISABLED=true` → 503 «Демо временно выключено» |

## Изменения API и схемы

Схема не меняется.

- `POST /sandbox` — поле `mode`: `ready` (по умолчанию) или `guided`.
  Для `guided` в ответе `login: {email, password}`.
- `POST /sandbox/reset` — то же поле `mode`.
- `GET /sandbox/guide` — состояние шагов.
- `POST /sandbox/guide/{step}/fill` — заполнить шаг шаблоном; в ответе
  новое состояние.
- Конфиг: `SANDBOX_DISABLED`.

## Решения

- **Режим не хранится.** Шаг засчитывается по данным, поэтому у готового
  демо шаги справочников, истории и прогноза отмечены сами, а пароль
  пошагового живёт в браузере посетителя рядом с id демо.
- **Наполнение готового и пошагового демо — один путь**: «найти по имени,
  иначе создать». Уникальные индексы по `lower(name)` делают дубли
  невозможными даже без блокировки — она нужна, чтобы гонка кончалась
  «уже заполняется», а не 500.
- **Сессионная advisory-блокировка на отдельном соединении**, а не
  транзакционная: наполнение идёт через сервисы несколькими транзакциями.
- **Действия — только у текущего шага.** На телефоне девять шагов с
  кнопками занимали полтора экрана.
- **Обновление шагов после любой мутации** — одним `MutationCache`, а не
  в каждом хуке. Вход и выход помечены `meta.session`: после выхода
  шаги иначе перечитывались бы без сессии.
- **Аварийный рубильник — отдельный флаг** `SANDBOX_DISABLED`: ноль в
  `SANDBOX_MAX_ACTIVE` означает «по умолчанию».
- **Готовое демо осталось** второй кнопкой; из него есть выход в
  пошаговое — «Пройти по шагам с нуля».

## Что пошло не так

- **Дробные круассаны.** Генератор писал расход по формуле спроса с
  тремя знаками для любых единиц: на дашборде демо — «239,729 шт».
  Жило с первого дня, в готовом демо тоже; заметно стало только на
  скриншоте после приёмки. Штуки теперь целые в истории, при промотке и
  в неполных поставках.
- **Тест одновременности принимает два исхода** — успех и «уже
  заполняется», — поэтому мог бы проходить при любом коде. Проверил
  мутацией: без блокировки гонка упирается в уникальный индекс, и
  тест падает на ответах 500.
- **401 после выхода.** Глобальное обновление шагов срабатывало на саму
  мутацию выхода; а лента опрашивалась без сессии всегда — это было и
  раньше, просто выход никто не нажимал в браузерной проверке.
- **Раннбук** советовал выключать демо `SANDBOX_MAX_ACTIVE=0`, что не
  работало; **контракт** описывал ответ `/sandbox/reset` одним
  `redirect_to` и «полгода истории»; **приёмка руками** называла кнопку
  «Начать заново». Исправлено по живым ответам.
