# Фича: переезд на vitalness.ru/zapas

Первая из четырёх задач «личный сайт + Zapas на своём домене».

> Статус: в работе — код готов и проверен на стенде, переключение
> сервера ждёт DNS (домен не добавлен в панель Beget)
> Оценка: 5 ч · Факт: 3,5 ч без переключения

## Контекст и цель

Zapas живёт на `zapas.85.198.64.102.nip.io`. Для портфолио нужен свой
адрес: `vitalness.ru` — сайт о разработчике, `vitalness.ru/zapas` —
проект. nip.io уходит.

Домен куплен 2026-09-24 на REG.RU и делегирован на Beget. Сервер
Zapas — VPS того же Beget. Значит, Beget нужен только как DNS: и
портфолио, и Zapas отдаёт nginx на 85.198.64.102.

## Изменения API и схемы

Ручки и схема не меняются. Меняется, где приложение живёт:

| Что | Было | Стало |
|---|---|---|
| `APP_BASE_URL` | `https://zapas.85.198.64.102.nip.io` | `https://vitalness.ru/zapas`; слеш на конце срезается при загрузке |
| Проверка `Origin` (CSRF и создание демо) | строка целиком | схема и хост базы — `httpx.SameOrigin` |
| Путь cookie сессии и CSRF | `/` | путь базы: `/zapas/` |
| `redirect_to` песочницы | константа `/app/` | путь базы + `/app/` |
| Кабинет | `base: '/app/'`, API `/api/v1` | `base: '/zapas/app/'`, API из `base` — `web/src/lib/paths.ts` |
| Лендинг | `base: '/'` | `base: '/zapas/'`, ссылки через `%BASE_URL%` |
| nginx | свой `server` на nip.io | только `location /zapas/…` в `/etc/nginx/snippets/zapas.conf`; `server vitalness.ru` — в репозитории портфолио |
| Выкат, CI, сторож | проверки по nip.io | по `vitalness.ru/zapas/` с `--resolve`; сторож ругается на отсутствующий сертификат |
| OpenAPI | серверы nip.io | `https://vitalness.ru/zapas/api/v1`, пример `redirect_to` из живого ответа |

## Переключение

Когда `dns.google` отдаёт `85.198.64.102` для обоих имён. Сервер общий:
перед каждым `reload` — `nginx -t`, `restart nginx` не бывает.

1. **DNS.** `curl -s "https://dns.google/resolve?name=vitalness.ru&type=A"`
   и то же для `www` — в обоих `"data":"85.198.64.102"`. Не локальным
   резолвером: он за VPN.
2. **Сниппет Zapas** в `/etc/nginx/snippets/zapas.conf` — по
   `docs/runbooks/deploy.md`. Пока его никто не подключает, он ни на что
   не влияет.
3. **Сертификат** — по README портфолио: временный `bootstrap-http.conf`,
   `nginx -t`, `reload`, `certbot certonly --webroot -w /var/www/html -d vitalness.ru -d www.vitalness.ru`.
4. **Портфолио**: `scripts/deploy.sh`, затем `scripts/nginx.sh` — полный
   конфиг с `include` сниппета. С этого момента `/zapas/` отдаёт ещё
   старую сборку — посетителей на новом адресе пока нет.
5. **Zapas**: в `/etc/zapas/zapas.env` — `APP_BASE_URL=https://vitalness.ru/zapas`,
   затем `scripts/deploy.sh`. Проверка в конце скрипта ходит уже на
   `vitalness.ru/zapas/`.
6. **Вебхук Telegram** — команда из `docs/maintenance.md` (1.4) с новым
   адресом, затем `getWebhookInfo`: новый URL, `last_error_message` пуст.
   Удобный момент заодно сменить засвеченный токен бота.
7. **Снять nip.io**: `sites-enabled/zapas` и `sites-available/zapas`
   (копию оставить в `/root`), `nginx -t`, `reload`,
   `certbot delete --cert-name zapas.85.198.64.102.nip.io`. Сертификат
   `85.198.64.102.nip.io` без `zapas` — чужой, не трогать.
8. **Глазами**: `docs/acceptance.md`, раздел 1, с телефона без VPN;
   соседи (`vadim-lubov-wedding.ru`) отвечают как раньше;
   `/srv/zapas/bin/watchdog.sh` молчит.
9. GitHub → About → ссылка `https://vitalness.ru/zapas/`.

## Решения

1. Хостинг Beget не используется, Beget — только DNS: сервер 85.198.64.102
   сам принадлежит Beget, и на нём уже есть nginx и certbot.
2. Zapas за префиксом, который срезает nginx: маршруты Go не меняются.
   Префикс знают только три места, и все берут его из `APP_BASE_URL`.
3. `server vitalness.ru` принадлежит репозиторию портфолио, Zapas
   поставляет только свои `location`. Следующий проект на домене
   добавит свой сниппет и одну строку `include`.
4. Конфиг nginx по-прежнему ставит человек, а не выкат: так записано в
   `docs/runbooks/deploy.md`, и сервер общий. Сначала я встроил установку
   сниппета в `deploy.sh` и `deploy.yml` — откатил, наткнувшись на это
   правило.
5. nip.io не поддерживается и снимается целиком (решение владельца).
6. Cookie с путём `/zapas/`: на домене будут и другие проекты, и
   сессии Zapas незачем уходить на их серверы.
7. Локальная разработка тоже под `/zapas/` (`APP_BASE_URL` по умолчанию
   `http://localhost:5173/zapas`, прокси Vite срезает префикс как nginx):
   дев и прод не расходятся по путям.

## Что пошло не так

- **Проверка `Origin` сравнивала строку целиком.** Браузер шлёт `Origin`
  без пути, а база путь получила. После переезда отвергался бы каждый
  изменяющий запрос: кабинет открывается, ни одна кнопка не работает.
  Найдено чтением кода до переезда, закрыто тестом, тест проверен
  мутацией.
- **k6 потерял бы сессию.** Cookie с путём `/zapas/` банка k6 для корня
  не отдаёт. Регрессия моя же; поймана прогоном на стенде.
- **Автоматизация nginx** против записанного правила — откачена (решение 4).
- **Раннбук `sandbox-abuse`**: блок бана без `X-Real-IP` — старая
  скрытая ошибка, найдена при правке путей.
- **Сторож молча пропускал проверку сертификата**, если файла нет.
- **Инструменты**: PowerShell забирал `-v` у `scripts/go.ps1` как
  `-Verbose` (поправлено: аргументы из `$args`); `grep -c $'\r'` в Git
  Bash насчитал 116 CR там, где их 0; локальный DNS за VPN отдаёт
  fake-ip из 198.18.0.0/15; `openssl req` в Git Bash путает пути.
- Домен не добавлен в панель Beget — серверы имён отвечают REFUSED.
  Переключение ждёт этого.
