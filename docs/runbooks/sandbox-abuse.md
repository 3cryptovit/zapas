# Демо используют не по назначению

Песочница открыта без регистрации — в этом её смысл и в этом её риск.
Здесь описано, как понять, что происходит, и что с этим делать.

## Как это устроено в обычном режиме

Кнопка «Открыть демо» заводит отдельную организацию с полугодом
истории и сразу пускает в неё. Ограничения:

| | |
|---|---|
| Живёт | 24 часа (`SANDBOX_TTL`) |
| Одновременно | не больше 60 (`SANDBOX_MAX_ACTIVE`) |
| С одного адреса | 5 в час (`SANDBOX_PER_IP_HOURLY`) |
| Убирает | задача `sandbox:cleanup`, каждый час в :30 |

Достигнут предел живых демо — новые не создаются, лендинг показывает
запись вместо кнопки. Это осознанный выбор: лучше показать видео, чем
уронить машину, на которой живут ещё пять проектов.

## Признаки, что что-то не так

Сторож (`zapas-watchdog`) пришлёт сообщение при переполнении диска или
нехватке памяти. Но до этого можно заметить раньше:

```bash
# Сколько сейчас живых демо
sudo -u postgres psql -qtA -d zapas -c \
  "select count(*) from tenants where is_sandbox and expires_at > now()"

# Откуда приходят: адрес клиента пишет nginx, а не приложение —
# в журнале сервиса его нет.
grep 'POST /zapas/api/v1/sandbox' /var/log/nginx/access.log \
  | awk '{print $1}' | sort | uniq -c | sort -rn | head

# Место на диске
df -h /
sudo -u postgres psql -qtAc "select pg_size_pretty(pg_database_size('zapas'))"
```

Нормально: единицы или десятки демо, адреса разные. Ненормально: сотня
запросов с одного адреса, база растёт на сотни мегабайт за час.

## Что делать

### Сначала — прибрать мусор

```bash
sudo -u postgres psql -qtA -d zapas -c \
  "select count(*) from tenants where is_sandbox and expires_at < now()"
```

Если просроченных много, значит воркер не справляется или стоит:

```bash
systemctl status zapas-worker
journalctl -u zapas-worker --since '1 hour ago' --no-pager | grep -i 'sandbox\|error'
systemctl restart zapas-worker
```

### Прикрутить лимиты

Правится `/etc/zapas/zapas.env`, применяется перезапуском API:

```bash
nano /etc/zapas/zapas.env      # SANDBOX_PER_IP_HOURLY=1, SANDBOX_MAX_ACTIVE=20
systemctl restart zapas-api
```

Уменьшать `SANDBOX_TTL` тоже можно, но осторожно: демо, открытое
работодателем, не должно протухнуть, пока он его смотрит. Час — разумный
минимум, меньше — уже во вред делу, ради которого демо существует.

### Закрыть конкретный адрес

Когда источник один и он явно машинный:

```bash
nginx -t && systemctl reload nginx
```

Блок в `/etc/nginx/snippets/zapas.conf`, рядом с остальными
`location` Zapas:

```nginx
location = /zapas/api/v1/sandbox {
    deny 203.0.113.5;
    proxy_pass http://127.0.0.1:8080/api/v1/sandbox;
    proxy_set_header X-Real-IP $remote_addr;
}
```

`X-Real-IP` обязателен. Приложение берёт адрес клиента только из него
и только с петли. Без заголовка каждый посетитель выглядит как
`127.0.0.1`, все делят один лимит «5 демо в час», и после пятого демо
кнопка перестаёт работать у всех.

Не забудьте `nginx -t` до `reload`: на этой машине битый конфиг
положит и свадебный сайт, у которого настоящие посетители.

### Выключить демо совсем

Крайняя мера, на время.

```bash
sudo -u postgres psql -d zapas -c \
  "update tenants set expires_at = now() where is_sandbox"
```

и в `/etc/zapas/zapas.env` поставить `SANDBOX_MAX_ACTIVE=0`, затем
`systemctl restart zapas-api`. Лендинг сам переключится на видео.

## Чего можно не бояться

Данные боевых организаций демо не видит: изоляция держится не на
проверках в коде, а на политиках RLS и отдельной роли БД без права их
обходить. Песочница — такой же тенант, как остальные, и её запросы
физически не достанут чужие строки.

Поэтому злоупотребление демо — это вопрос ресурсов машины, а не
утечки. Соответственно и лечится ресурсными мерами.
