# Проверка руками

Сценарии, которые нужно пройти глазами перед тем, как показывать проект.
Автотесты проверяют коды ответов, здесь проверяется то, что видит человек.

Каждый пункт: что сделать → что должно получиться. Если получилось
другое — это находка.

Быстрый путь: разделы 1, 2, 6 и 9 закрывают демо за десять минут.

---

## Где проверять

**Демо на проде** — https://vitalness.ru/zapas/, кнопка «Открыть
демо». Отдельная организация с 90 днями истории, живёт сутки,
регистрация не нужна. Подходит для всего, кроме Telegram: в демо
внешние каналы отключены намеренно.

**Локально** — `make dev`, затем `make seed`, вход
`owner@zapas.local` / `локальный-пароль-42`. Нужно для проверки
Telegram и для работы с пустой организацией.

Ограничение: пять демо в час с одного адреса. Повторное нажатие кнопки
возвращает в уже открытое демо, а не создаёт новое.

## 2. Дашборд

| Шаг | Ожидается |
|---|---|
| Посмотреть счётчики сверху | Пять чисел: нет в наличии, критично, заказать сегодня, в порядке, нет прогноза. Сумма равна общему числу позиций |

Ключевое: **ни одно количество не должно быть дробным там, где
поставщик возит коробками.** 1,3 коробки молока заказать нельзя.

## 3. Карточка позиции

Открыть любую позицию из дашборда.

| Шаг | Ожидается |
|---|---|
| График спроса | Тёмные столбики факта, пунктирная линия прогноза, светлая полоса коридора ±σ |
| Дни с нулевым остатком | Светлые столбики, подписаны как исключённые из обучения |
| График проекции остатка | Линия идёт вниз, пересекает ноль в дату «хватит до» |
| Блок «почему такой статус» | Все числа расчёта: остаток, в пути, позиция запаса, потребность, страховой запас, целевой уровень, недобор |
| Точность прогноза | Процент и модель (M0, M1 или M2) |

Проверка на согласованность: **целевой уровень минус позиция запаса,
округлённое вверх до кратности, должно совпасть с рекомендованным
количеством.** Если не сходится — это находка.

## 4. Движения

С карточки позиции или с дашборда.

| Шаг | Ожидается |
|---|---|
| Записать приход 10 | Остаток вырос на 10, статус пересчитался сразу, без обновления страницы |
| Записать расход 3 | Остаток уменьшился на 3 |
| Списать 1 без причины | Форма не даёт отправить, требует причину |
| Списать 1 с причиной «испортилось» | Записано, в ленте видна причина |
| Списать больше, чем есть | Отказ с сообщением, в котором указан реальный остаток |
| Записать движение завтрашним числом | Отказ: события из будущего не принимаются |
| Записать движение десятидневной давности | Отказ: дальше семи дней назад нельзя |

**Сторнирование.** Найти запись в ленте, нажать «Сторно».

| Шаг | Ожидается |
|---|---|
| Сторнировать приход | Появляется обратная запись, остаток вернулся |
| Сторнировать её же ещё раз | Отказ: повторное сторно запрещено |
| Посмотреть на исходную запись | Помечена как сторнированная, но не исчезла и не изменилась |

Журнал неизменяем: **записи не редактируются и не удаляются, только
гасятся обратной.**

## 6. Заказы

| Шаг | Ожидается |
|---|---|
| С дашборда нажать «Заказать» у поставщика | Черновик заказа со строками из рекомендации |
| Открыть заказ | Виден готовый текст для отправки поставщику |
| Проверить текст | Количества в единицах заказа, без хвостов вида «2.000 кор.» |
| Изменить количество в строке | Сохраняется, пока заказ черновик |
| Нажать «Отправить» | Статус «отправлен» сразу, без обновления страницы: кнопка «Отправить» сменилась на «Принять поставку». На дашборде у этих позиций появилось «в пути» |
| Вернуться на дашборд | **Эти позиции больше не советуют заказать повторно** |
| Изменить отправленный заказ | Отказ: менять можно только черновик |
| Нажать «Принять» | Поля «Привезли» заполнены заказанным без хвостов: «10», а не «10.000» |
| Провести приёмку | Статус «принят», приход записан, «в пути» обнулилось |
| Принять с недовозом (указать меньше) | Приход на фактическое, расхождение зафиксировано, появилось уведомление |
| Нажать «Отправить» у принятого | Отказ |

Ключевое: **пока заказ в пути, система не советует заказать то же
самое второй раз.** Это и есть смысл поля «в пути».

### 9а. Пошаговое демо

С лендинга — кнопка «Пройти демо по шагам».

| Шаг | Ожидается |
|---|---|
| Нажать кнопку | Пустая кофейня: дашборд без позиций, над ним панель «Шаг 1 из 9: Поставщики» и «Ваш вход: demo-…@sandbox.local · показать пароль» |
| Нажать «показать пароль» | 12 символов без похожих букв (нет 0/o, 1/l/i) |
| «Добавить в „Настройках“» у шага 1, завести поставщика руками | Шаг засчитан так же, как шаблоном: панель перешла к «Позициям» |
| Нажать кнопку шаблона у каждого шага подряд | Шаг за шагом до «Шаг 8 из 9: Время»; на дашборде 38 позиций со статусами, количества штук — целые |
| Нажать кнопку шаблона второй раз (из другой вкладки) | «Уже заполнено, повтор ничего не дублирует»; поставщиков по-прежнему 4 |
| «+7 дней» в панели | «Шаг 9 из 9: Уведомления» |
| «Открыть ленту» → «Прочитать всё» | «Все шаги пройдены» |
| «Выйти», войти с показанными логином и паролем | Та же кофейня, та же панель |
| Открыть готовое демо, развернуть панель | Справочники, история и прогноз уже отмечены; кнопка «Пройти по шагам с нуля» даёт пустое пошаговое демо |
| Телефон, панель раскрыта | Действия только у текущего шага, остальные — строкой; горизонтальной прокрутки нет |

Ключевое: **шаг засчитывается по данным, а не по кнопке**. Сделанное
руками и шаблоном неотличимо — значит, панель показывает настоящий
порядок работы с системой, а не отдельный сценарий для демо.

## 13. Визуальная система

Цвет в интерфейсе дозирован: один синий акцент на действия и «вы здесь»,
красный, жёлтый и зелёный — только у статусов. Проверять отдельно:
ошибка здесь не ломает работу, но делает главный экран шумным.

| Шаг | Ожидается |
|---|---|
| Открыть дашборд, где есть все статусы | «Закончилось» — сплошная красная плашка, «Критично» — мягкая красная, «Заказать сегодня» — жёлтая, «Хватает» — зелёная, «Нет прогноза» — серая. У каждой точка и подпись |
| Отойти от экрана на два шага | Красное находится глазом сразу, остальное не спорит за внимание |
| Посмотреть на счётчики | Число крупное, ноль в тревожной плитке — бледный |
| Открыть список заказов | Черновик серый, «отправлен» синий, «принят» зелёный, отменённый зачёркнут |
| Открыть карточку позиции | На графике спроса: серые столбики факта, светлые — исключённые дни, синяя линия прогноза, светло-синий коридор. На графике остатка видна жёлтая пунктирная линия страхового запаса, даже если проекция ушла в минус |
| Открыть на телефоне | Боковой панели нет, меню — по кнопке слева вверху; полоса демо в две строки |
| Проверить шрифт | Текст набран Inter; в DevTools → Network есть два файла `inter-…woff2`, оба 200 |
| Включить в системе оттенки серого | Статусы различимы по подписи и по плотности плашки |
| Напечатать дашборд в PDF (Ctrl+P) | Цвет статусов сохранился |

## Что уже проверяется автоматически

Эти сценарии закрыты тестами и в ручной проверке не нуждаются:

- изоляция организаций на уровне базы — политики RLS, отдельная роль
  без права их обходить;
- конкурентность — 50 одновременных списаний одной позиции;
- идемпотентность — повтор запроса с тем же ключом не создаёт второе
  движение;
- согласованность — остаток равен сумме движений по всем позициям;
- точность прогноза — WAPE не хуже 20% на данных с фиксированным seed;
- скорость — дашборд и запись движения на базе с миллионом движений
  (см. [performance/](performance/README.md));
- кодировки CSV — UTF-8, UTF-8 с BOM, CP1251, двоичный файл, UTF-16;
- промотка времени с автопилотом на две недели подряд;
- ключ повтора запроса без `crypto.randomUUID` — вне HTTPS и в старом Safari;
- после отправки заказа и проведения пересчёта их карточки перечитываются.

```bash
make test        # 15 пакетов под детектором гонок
make api-lint    # контракт API
```
