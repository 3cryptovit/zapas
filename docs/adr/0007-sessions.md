# ADR-007. Серверные сессии в httpOnly-cookie

Статус: принято · 19.09.2026

## Контекст

Кабинет — обычное веб-приложение с одним доменом. Отдельных мобильных клиентов
и сторонних интеграций в MVP нет. Выход из системы должен действительно
прекращать доступ, в том числе для песочницы, которую удаляют по истечении суток.

## Решение

Случайный токен на 32 байта в cookie: `httpOnly`, `Secure`, `SameSite=Lax`,
срок 14 дней с продлением. В БД хранится только SHA-256 токена — дамп базы
не даёт войти ни под кем.

CSRF — double-submit: отдельный токен в заголовке `X-CSRF-Token` плюс проверка
`Origin` для изменяющих запросов.

## Последствия

- Выход и удаление тенанта немедленно закрывают доступ: сессия удаляется строкой.
- Токен недоступен из JavaScript, поэтому XSS не уносит сессию.
- Каждый запрос требует чтения строки сессии из БД. При целевых нагрузках
  это дешевле, чем последствия невозможности отозвать доступ.
- `SameSite=Lax` достаточен, потому что лендинг, кабинет и API живут на одном
  домене за общим Nginx.

## Отвергнуто

**JWT в localStorage.** Отзывать нечего до истечения срока, а доступность из
JavaScript превращает любой XSS в угон аккаунта. Statelessness здесь ничего
не даёт: приложение и так ходит в БД на каждом запросе.
