# ADR-003. sqlc вместо ORM

Статус: принято · 19.09.2026

## Контекст

Тяжёлые места системы — запрос дашборда, сборка дневного расхода и запись
движения с блокировкой строки. Все три пишутся как конкретный SQL с конкретным
планом; ORM в них только мешает.

## Решение

`pgx/v5` как драйвер, `sqlc` для генерации типобезопасного кода из файлов
`queries/*.sql`. Количества генерируются как `decimal.Decimal`, идентификаторы —
как `uuid.UUID` (см. `sqlc.yaml`). CI проверяет, что `sqlc generate` не меняет
рабочее дерево.

## Последствия

- Каждый запрос виден целиком, к нему можно приложить `EXPLAIN ANALYZE`
  (`docs/performance/`).
- Ошибка в имени колонки ловится на генерации, а не в рантайме.
- N+1 не возникает незаметно: чтобы его написать, нужно осознанно завести цикл.
- Схема меняется в два шага: миграция, затем `make sqlc`.
- Динамические фильтры журнала (позиция, тип, период, автор) приходится делать
  либо несколькими запросами, либо через `coalesce($n, column)`.

## Отвергнуто

**GORM.** Скрывает генерируемый SQL, неявно тянет связи и плохо сочетается
с блокировкой строки остатка и `FOR UPDATE SKIP LOCKED` в outbox.
