## С чего начать чтение

Если проект достался в поддержку — начинать с
[maintenance.md](maintenance.md), там порядок действий по шагам.

Если хотите понять, как оно устроено:

1. [spec.md §1](spec.md) — зачем всё это и какую задачу владельца снимает.
2. [architecture.md](architecture.md) — как устроено.
3. [adr/0002](adr/0002-movement-journal.md) и [adr/0005](adr/0005-tenant-isolation.md) —
   два решения, вокруг которых собрано остальное.

## Шаблон ТЗ фичи

```
# Фича: <название>

## Контекст и цель
## Требования и крайние случаи
## Изменения API и схемы
## План тестов
## Оценка: N ч
## Факт: N ч
```

Сравнение оценки и факта — то же, что целевые команды меряют в KPI, поэтому
поле «Факт» заполняется всегда, даже когда расхождение неприятное.
